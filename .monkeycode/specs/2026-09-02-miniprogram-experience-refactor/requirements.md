# 小程序体验焕新重构需求

## 介绍

本需求针对“小牛育儿”微信小程序客户端进行体验重构。重构聚焦家长首次进入后的理解成本、栏目识别和核心操作路径，采用白底、清爽、传统小程序的信息组织方式，保留现有页面路径、后端接口、登录状态、孩子档案隔离和核心业务能力。

## 术语

- **首页**：小程序默认进入页面，承担品牌展示、首要行动引导和功能分区导航。
- **核心行动**：成长痛点识别、今日行动、表现反馈、成长报告中的当前优先操作。
- **功能板块**：首页中指向一个明确业务场景的入口区域。
- **传统小程序布局**：顶部 Banner、快捷入口、分组卡片、底部原生 TabBar 的页面结构。
- **清爽视觉系统**：白色或浅色背景、低饱和品牌色、清晰层级、有限阴影和统一图标风格。
- **短标题**：用于成长痛点入口的 2 至 6 字标题，完整情境通过副标题、症状和详情内容补充。
- **内容媒体**：与文字内容关联的封面图、步骤图、示例图、对比图或短视频。
- **运营后台**：供管理员和运营人员管理内容、媒体、训练、营养、会员配置、用户运营和客服工单的 Web 系统。
- **媒体资产**：运营人员上传并关联到文章、成长痛点、训练或营养内容的图片、音频和视频。
- **内容版本**：一次可追溯的内容保存结果，包含正文、媒体关联、发布状态、操作人员和保存时间。
- **客服工单**：由家长反馈生成并由运营人员分配、跟进、回访和关闭的服务记录。

## 需求

### 需求 1：首页信息架构

**用户故事：** 作为家长，我希望进入首页后立即理解小程序能解决哪些家庭问题，从而选择下一步操作。

#### 验收标准

1. 当家长打开首页时，系统应按“顶部 Banner、快捷入口、核心行动、内容板块、成长服务”顺序展示主要信息。
2. 当家长查看首页功能板块时，系统应为每个板块同时展示统一图标、2 至 6 字短标题和家庭场景描述。
3. 当家长查看首页时，系统应在首屏展示一个当前核心行动，并展示单一明确的按钮文案。
4. 当家长还没有当前成长痛点识别结果时，系统应将成长痛点识别作为核心行动，并提供进入识别流程的入口。

### 需求 7：图文内容表达

**用户故事：** 作为家长，我希望看见具体动作和家庭场景的图示，从而更容易理解并照着完成。

#### 验收标准

1. 当成长痛点详情包含操作步骤时，系统应支持在文字步骤前后展示对应的步骤图或动作示意图。
2. 当成长痛点详情需要说明差异时，系统应支持展示“这样做”和“可以这样调整”的示例对比图。
3. 当内容没有可用图片时，系统应继续展示完整文字、步骤和家长话术。
4. 当图片加载失败时，系统应展示图片说明文字并保持详情页其他内容可用。
5. 当家长浏览图文内容时，系统应保证图片比例、清晰度、替代文本和触控查看体验适配小程序页面。

### 需求 2：视觉与组件系统

**用户故事：** 作为家长，我希望页面清爽、熟悉、容易阅读，从而降低使用压力。

#### 验收标准

1. 系统应使用白色或浅色页面底色、一个主品牌色和有限的辅助色表达交互状态。
2. 系统应为 Banner、入口图标、卡片、标签、按钮、列表和状态反馈提供统一视觉规则。
3. 系统应保持标题、正文、辅助文字和按钮文字的字号层级，并保证长文本在小屏设备中完整换行。
4. 系统应为所有可点击入口提供至少 44pt 等效触控区域。
5. 系统应使用同一套线性或面性图标风格表达首页和主要业务入口。

### 需求 3：栏目与导航清晰度

**用户故事：** 作为家长，我希望知道每个栏目适合什么时候使用，从而减少反复试错。

#### 验收标准

1. 系统应将首页入口归入“成长痛点、今天怎么做、成长记录、家庭内容”四类功能分组。
2. 当家长点击功能入口时，系统应沿用现有页面路径打开对应业务页面。
3. 系统应在栏目标题或副标题中说明适用场景，例如写作业、吃饭、睡前和亲子共读。
4. 系统应保留原生底部 TabBar，并维持首页、功能、成长和我的四个一级入口。

### 需求 4：状态与反馈体验

**用户故事：** 作为家长，我希望在网络慢、内容为空或功能加载中时知道当前状态，从而决定是否继续操作。

#### 验收标准

1. 当首页数据加载时，系统应展示与内容结构匹配的骨架或占位状态。
2. 当首页接口加载失败时，系统应保留可用的本地快照，并展示可理解的恢复提示和重试入口。
3. 当功能没有内容时，系统应展示原因说明和一个可执行的下一步入口。
4. 当家长点击核心行动后，系统应展示操作反馈，并在流程完成后返回对应的结果或下一步建议。

### 需求 5：渐进式发布与兼容

**用户故事：** 作为产品维护者，我希望逐步替换页面并保留回退能力，从而控制重构风险。

#### 验收标准

1. 系统应保留现有页面路径、后端接口字段和登录刷新机制。
2. 系统应支持按页面或功能开关启用新版视觉与布局。
3. 当新版页面出现运行错误时，系统应提供安全启动和本地状态恢复能力。
4. 每个重构阶段应完成小程序语法检查、核心链路回归和真机体验检查后再扩大范围。

### 需求 6：核心链路可理解性

**用户故事：** 作为第一次使用的小程序家长，我希望从具体成长痛点开始获得清晰的行动建议。

#### 验收标准

1. 当家长首次进入首页时，系统应解释成长痛点识别、今日行动、成长报告和AI问答之间的关系。
2. 当家长选择年龄或家庭场景时，系统应显示当前选择和下一步操作。
3. 当家长获得建议时，系统应区分“现在做什么”“观察什么”和“何时寻求专业帮助”。
4. 当家长从首页进入 AI 问答时，系统应携带当前孩子和家庭场景上下文。

### 需求 8：运营内容管理

**用户故事：** 作为运营人员，我希望通过运营后台更新图片、文章和成长痛点内容，从而持续维护小程序内容。

#### 验收标准

1. 当运营人员创建或编辑内容时，运营后台应支持保存标题、摘要、正文、分类、年龄段、标签、封面和正文媒体。
2. 当运营人员上传媒体时，运营后台应校验文件类型、大小和尺寸，并生成可供小程序访问的媒体地址。
3. 当运营人员替换已关联图片时，系统应生成新内容版本并保留历史版本记录。
4. 当小程序请求已发布内容时，内容接口应只返回当前有效的发布版本。
5. 当远程内容不可用时，小程序应使用本地降级内容维持成长痛点核心浏览链路。

### 需求 9：完整运营平台

**用户故事：** 作为管理员，我希望在同一个后台管理主要运营对象，从而减少分散配置和人工数据库操作。

#### 验收标准

1. 运营后台应提供媒体、文章、成长痛点、家庭训练、营养内容、会员配置、用户运营和客服工单模块。
2. 当管理员调整会员展示配置时，系统应记录配置版本、操作人员和生效状态。
3. 当运营人员查看用户运营模块时，系统应展示授权范围内的用户分层、活跃状态和服务记录。
4. 当管理员执行内容、配置或工单状态变更时，系统应记录操作前数据、操作后数据、操作人员和操作时间。
5. 当运营人员的角色权限不包含目标操作时，运营后台应返回权限提示并保留当前页面数据。

### 需求 10：完整内容发布流程

**用户故事：** 作为内容负责人，我希望内容经过审核、定时发布和版本管理，从而控制内容质量和发布时间。

#### 验收标准

1. 当编辑人员保存内容时，系统应将内容保存为草稿版本。
2. 当编辑人员提交审核时，系统应将指定版本进入待审核状态并记录提交人员和提交时间。
3. 当审核人员批准内容时，系统应允许立即发布或设置计划发布时间。
4. 当计划发布时间到达时，系统应将已批准版本切换为发布状态并刷新内容缓存。
5. 当运营人员下线内容时，系统应停止向小程序返回该内容并保留历史版本。
6. 当管理员恢复历史版本时，系统应基于历史内容创建新的草稿版本。

### 需求 11：客服工单回访

**用户故事：** 作为家长，我希望提交问题后获得人工回访，从而解决需要进一步沟通的问题。

#### 验收标准

1. 当家长提交反馈时，系统应创建包含反馈类型、内容、联系方式、来源页面和用户标识的客服工单。
2. 当运营人员处理工单时，运营后台应支持分配负责人、设置优先级、记录处理备注和更新处理状态。
3. 当运营人员完成电话或微信回访时，运营后台应记录回访时间、回访方式和处理结果。
4. 当家长查看反馈历史时，小程序应展示工单的当前处理状态和最近一次公开进展。
5. 当工单包含联系方式时，运营后台应按角色权限展示联系方式并记录访问行为。

### 需求 12：后端兼容与内容迁移

**用户故事：** 作为产品维护者，我希望运营能力扩展期间核心业务保持稳定，从而分阶段完成后台升级。

#### 验收标准

1. 系统应继续沿用现有登录、孩子档案、支付、会员、成长记录、训练反馈和阶段报告接口契约。
2. 当成长痛点内容迁移到服务端后，内容接口应保持现有页面需要的标题、症状、行动、话术和观察字段。
3. 当新内容字段尚未配置时，接口应返回兼容默认值并保留现有字段。
4. 当运营内容发生发布、下线或版本恢复时，系统应刷新相关列表、详情和推荐缓存。
5. 每次数据库结构升级应通过可追溯迁移执行，并保留升级状态和失败记录。

## 范围边界

- 本阶段覆盖 `miniprogram/`、`admin-portal/`、后端运营接口、内容接口和必要的数据库迁移。
- 运营后台首期覆盖媒体、文章、成长痛点、家庭训练、营养内容、会员配置、用户运营和客服工单。
- 真人服务首期采用反馈工单回访，家长通过现有反馈入口提交问题，运营人员通过后台跟进。
- 现有登录、孩子档案、支付、会员权益计算、训练完成、成长记录和阶段报告核心逻辑保持接口兼容。
- 页面路径和原生底部 TabBar 保持兼容。
- 全量页面以首页的信息架构和视觉令牌为共同基准，按核心链路优先级分组迁移。
- 产品必须保留功能分类导航，功能入口应直接展示家长要解决的具体成长痛点。

## 全量重构补充范围

### 需求 13：家庭行动信息架构

**用户故事：** 作为家长，我希望从今天要做的事情开始使用小程序，从而快速获得可执行的陪伴建议。

#### 验收标准

1. 系统应将首页定位为品牌展示、重点专题曝光和功能导航页面。
2. 首页应使用可自动轮换的 Banner 展示广告或重点专题，并支持点击进入对应业务页面。
3. 首页应在 Banner 下方使用清爽的功能图标入口，帮助家长快速进入常用能力、内容、训练、问答和成长服务。
4. “功能”一级页面应按家庭场景和具体表现组织入口，家长应能从写作业、吃饭、睡前、出门、亲子共读等场景进入对应内容。
4. “成长”一级页面应展示行动完成、家长观察、阶段变化和周总结，形成从行动到记录的连续链路。
5. “我的”一级页面应集中展示孩子档案、会员状态、反馈进展、客服入口和账号设置。

### 需求 14：全页面体验一致性

**用户故事：** 作为家长，我希望进入不同功能页面时仍能理解页面结构和操作方式，从而减少学习成本。

#### 验收标准

1. 所有一级页面和二级页面应使用统一的页面背景、页面头部、标题层级、卡片、按钮、标签、列表和状态反馈样式。
2. 所有正式用户界面应使用统一图标风格，功能图标不得依赖 Emoji 表达。
3. 页面应使用温暖品牌色表达重点、青绿色表达主要行动、有限辅助色表达状态，并保持颜色语义一致。
4. 文章、食谱、训练、知识点和成长痛点详情应使用统一的内容阅读结构：场景说明、判断依据、今天行动、家长话术、观察信号和边界提示。
5. 登录、加载、空数据、失败、重试、完成和无权限状态应在所有业务模块中提供一致的反馈表达。
6. 系统应使用 `#FAF8F5` 作为小程序页面背景、`#FFFFFF` 作为卡片背景、`#ECEFEB` 作为卡片边框和分割线。
7. 系统应使用 `#6AAE98` 作为主品牌色、`#397A68` 作为主品牌深色、`#E6F7ED` 作为主色浅底、`#F28C72` 作为行动强调色。
8. 当页面展示普通卡片、列表项、输入框或次要按钮时，系统应使用可见边框建立内容层级。
9. 当页面展示主行动卡或悬浮卡片时，系统应使用 `0 4px 16px rgba(106, 174, 152, 0.12)` 等效轻阴影；普通卡片应主要通过边框区分层级。
10. 系统应使用“做事与学习 `#F5E8BC`、情绪与配合 `#E7DDF2`、说话与表达 `#DDEBF3`、同伴与相处 `#F3DFE3`、身体与适应 `#DDEDE5`”表达五类成长痛点。
11. 系统应使用 `#2F3432`、`#626A66`、`#929995` 分别表达主标题、正文和辅助文字。
12. 系统应采用 8px 栅格、16px 页面安全边距、14 至 18px 卡片圆角、12 至 16px 按钮圆角和全圆角胶囊标签。

### 需求 15：核心业务链路重构

**用户故事：** 作为第一次使用的家长，我希望完成一次完整的成长行动，从而理解小程序的长期价值。

#### 验收标准

1. 家长应能从功能页或重点专题进入成长痛点识别、查看详情、开始今日行动、记录变化并返回成长页。
2. 家长从成长痛点详情进入 AI 问答时，系统应携带当前孩子、年龄和家庭场景上下文。
3. 家长应能从功能场景直接进入相关内容、训练、营养建议或成长记录入口。
4. 家长应能从成长页查看本周行动、历史记录和阶段总结，并返回当前主行动。
5. 会员页应根据未开通、试用中、已开通和已到期状态展示对应权益和下一步操作。
6. 反馈页应能完成提交、查看处理进展和进入客服回访链路。

### 需求 16：全量页面交付

**用户故事：** 作为产品维护者，我希望所有用户可见页面都完成新体验迁移，从而保证版本发布后的整体一致性。

#### 验收标准

1. 首页、功能、成长、我的四个一级页面必须完成新信息架构和新视觉迁移。
2. 成长痛点、今日行动、训练、营养、内容、AI、会员、孩子档案、反馈、报告和账号页面必须完成统一页面结构迁移。
3. 所有迁移页面必须保留现有路径、接口调用、事件绑定、孩子隔离和登录刷新行为。
4. 所有迁移页面必须覆盖加载、空态、错误、重试、未登录和无孩子档案状态。
5. 全量迁移完成后，自动检查不得发现旧主题色、Emoji 正式图标或内部实现状态词出现在正式用户界面中。

## 验收重点

- 首次用户能在 5 秒内说出首页至少三个功能分区的用途。
- 首页核心行动在视觉上具有最高优先级，且同一时刻只呈现一个主按钮。
- 白底、图标、Banner、卡片和列表在 iOS 与 Android 真机上保持一致层级。
- 现有登录、孩子切换、成长痛点识别、今日行动、AI 问答和成长报告入口可正常到达。
- 家长应能从“功能”入口直接进入“叫了不动”“做着分心”“换活动就哭”“说话不清”“不会一起玩”等成长痛点板块。
- 当家长进入成长痛点板块时，系统应在同一板块内提供看原因、今天做、问小牛、查看方法和记录变化入口。
- 运营人员应能完成内容草稿、审核、定时发布、下线和历史版本恢复闭环。
- 客服工单应能完成提交、分配、回访、记录结果和关闭闭环。
- 家长从功能页或重点专题完成一次“发现问题 → 今天行动 → 记录变化 → 查看成长”的主链路时，页面结构和操作文案应保持连续。
