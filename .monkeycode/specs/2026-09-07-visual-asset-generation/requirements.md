# 小程序视觉资产批量生成需求

## 介绍

本需求用于一次性规划“小牛育儿”微信小程序的 GPT Image 2.0 批量视觉资产。当前小程序注册 36 个页面，仅有 8 张本地 PNG，首页多个入口复用 TabBar 图，部分正式界面使用文字或 Emoji 充当图标。资产建设覆盖品牌形象、一级入口、内容封面、场景插画、空状态、分享背景和成就徽章，同时保留动态文字、状态数据和交互控件的代码渲染能力。

## 术语

- **母版资产**：由图片模型生成的一张独立原始画面，用于派生不同尺寸、格式或颜色状态。
- **包内资产**：随微信小程序代码包发布的品牌标识、TabBar、固定功能图标和默认占位图。
- **远程媒体**：通过运营后台上传并由内容接口返回 URL 的 Banner、封面、场景图和步骤图。
- **动态文字安全区**：画面中预留给 WXML 或海报绘制逻辑叠加标题、说明和数据的区域。
- **内容模板**：用于持续生成同类文章、食谱、训练或场景图片的固定构图及 Prompt 规则。
- **源图片交付包**：产品维护者生成并上传到当前工作区的单个文件夹或 ZIP，包含本批次全部选定原图。
- **资产接入清单**：记录源文件、资产 ID、派生文件、包内路径、远程 URL、消费者页面和接入状态的映射表。

## 需求

### 需求 1：统一视觉语言

**用户故事：** 作为家长，我希望不同页面的图片和图标具有一致的视觉语言，从而快速识别品牌和功能。

#### 验收标准

1. 当系统展示生成资产时，系统应采用温暖、克制、低饱和的现代亲子编辑插画风格。
2. 当系统展示人物时，系统应呈现真实可信的中国家庭日常场景和积极、平等的亲子互动。
3. 当系统展示品牌色时，系统应优先使用 `#6AAE98`、`#397A68`、`#F28C72` 及现有五类成长主题浅色。
4. 当同一概念出现在多个页面时，系统应复用同一母版资产。
5. 当画面需要标题或数据时，系统应通过动态文字安全区承载代码叠加内容。

### 需求 2：固定图标资产

**用户故事：** 作为家长，我希望功能入口使用清晰且一致的图标，从而在浏览时快速定位目标功能。

#### 验收标准

1. 当家长查看四个一级 Tab 时，系统应为首页、功能、成长和我的展示四个独立图标及对应激活态。
2. 当家长查看首页快捷入口时，系统应为八个核心功能展示八个语义唯一的图标。
3. 当家长查看观察、营养、家庭场景和学习主题时，系统应使用对应领域图标集。
4. 当家长查看正式业务界面时，系统应使用统一图标替代 Emoji 和文字占位图标。
5. 当图标显示在 24 至 48 像素区域时，图标主体应保持可辨认轮廓。

### 需求 3：Banner 与内容封面

**用户故事：** 作为家长，我希望通过具体家庭场景图片理解内容主题，从而选择符合当前情况的内容。

#### 验收标准

1. 当首页展示轮播内容时，系统应提供成长观察、家庭支持助手和成长记录三类 Banner。
2. 当营养页面展示食谱时，系统应为三个本地示例食谱和五个通用分类提供可复用封面。
3. 当育儿内容缺少专属封面时，系统应按情绪、习惯、认知、社交和营养五类使用默认封面。
4. 当发展专区展示高频场景时，系统应提供十张可解释家庭行为和空间关系的场景插画。
5. 当内容媒体加载失败时，系统应继续显示标题、说明和可执行操作。

### 需求 4：状态与分享资产

**用户故事：** 作为家长，我希望空数据、完成鼓励和分享页面具有友好的视觉反馈，从而理解当前状态和下一步操作。

#### 验收标准

1. 当页面进入无孩子、无观察、无记录、无食谱、无文章、无搜索结果、无练习或媒体失败状态时，系统应展示对应通用空状态插画。
2. 当家长达成阶段目标时，系统应按五个鼓励等级展示对应成就徽章。
3. 当家长分享观察结果、周总结、通用内容或会员邀请时，系统应使用对应的无文字分享背景。
4. 当分享内容包含孩子名称、分数或日期时，系统应通过运行时代码绘制动态数据。

### 需求 5：生成与交付规范

**用户故事：** 作为产品维护者，我希望批量生成结果可以直接校验和接入，从而降低人工整理成本。

#### 验收标准

1. 当生成包内图标时，生成流程应输出透明背景 PNG 母版和压缩后的 WebP 派生文件。
2. 当生成 Banner、封面和场景图时，生成流程应输出无文字、无水印、无品牌混淆元素的高分辨率母版。
3. 当生成分享背景时，生成流程应在四周保留至少 8% 安全边距，并为动态文字保留连续低细节区域。
4. 当生成任务完成时，交付物应按资产 ID、文件名、用途、尺寸、Prompt 和接入位置形成清单。
5. 当图片进入小程序代码包时，构建检查应验证文件尺寸、格式、透明通道、命名和包体增量。

### 需求 6：源图片文件夹交付与自动接入

**用户故事：** 作为产品维护者，我希望把全部生成结果放入一个文件夹上传，从而由接入流程完成分类、转换、服务器发布和小程序挂载。

#### 验收标准

1. 当产品维护者整理生成结果时，源图片交付包应采用单层目录，并为每个资产 ID 保留一张最终选定图片。
2. 当产品维护者命名源图片时，文件名主体应与 Prompt 文档中的资产 ID 完全一致，扩展名应为 `.png`、`.jpg`、`.jpeg` 或 `.webp`。
3. 当产品维护者交付完整批次时，源图片交付包应包含 `001` 至 `106` 对应的 106 个唯一资产 ID。
4. 当产品维护者上传源图片交付包时，上传目标应为当前工作区的 `.monkeycode/incoming/visual-assets-2026-09-07/`，ZIP 文件应命名为 `niuniu-visual-assets-106.zip`。
5. 当接入流程读取源图片交付包时，接入流程应校验文件数量、资产 ID、重复项、图片可读性、像素尺寸、比例、透明通道和文件大小。
6. 当源图片通过校验时，接入流程应生成压缩图、缩略图、TabBar 状态图和其他资产清单指定的派生文件。
7. 当固定视觉资产完成后处理时，接入流程应写入 `miniprogram/images/generated/` 并更新 WXML、WXSS、JavaScript 和 `app.json` 中的资源引用。
8. 当内容视觉资产完成后处理时，接入流程应通过媒体中心发布到服务器 `uploads/media` 存储链路，并将返回 URL 写入对应 Banner、文章、食谱、训练、发展场景和分享配置。
9. 当全部资产完成挂载时，接入流程应输出资产接入清单，并验证 36 个注册页面的资源引用、加载降级、代码包体积和真机显示效果。

### 需求 7：代码绘制边界

**用户故事：** 作为产品维护者，我希望高频状态和数据保持可编程，从而确保交互准确和页面性能稳定。

#### 验收标准

1. 当页面展示箭头、关闭、加号、单选、复选、开关或选择器时，系统应使用代码或微信原生控件。
2. 当页面展示进度条、分数环、趋势图、骨架屏或加载动画时，系统应使用 WXSS 和运行时数据绘制。
3. 当页面展示价格、日期、分数、百分比、标题或业务说明时，系统应使用动态文本渲染。
4. 当页面展示用户头像或孩子头像时，系统应优先使用用户提供的真实图片，并在图片缺失时使用生成的占位头像。

## 范围边界

- 本次规划覆盖 `miniprogram/app.json` 当前注册的 36 个页面和 3 个公共组件。
- 首次批量生成覆盖 106 个母版资产，尺寸和格式派生文件不计入母版数量。
- 文章正文图、训练步骤图、成长痛点步骤图和后续新增食谱图采用内容模板持续生成。
- 法律协议、表单控件、数据图表、加载动画和动态业务文字保持代码渲染。
- GPT Image 2.0 只负责原始视觉母版，裁切、压缩、重着色、透明通道检查和文件命名由后处理流程完成。
